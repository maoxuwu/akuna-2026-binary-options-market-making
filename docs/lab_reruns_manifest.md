# Post-publication lab re-runs — manifest

Scope: most lab rows concern the supplementary selective-quoting prototype;
rows identifying V46/V47 concern the submitted-strategy audit. Keep the build
column attached to every result. Historical labels `Line A` and `Line B`
mean the prototype and submitted strategy respectively; the `B-` prefix in
this manifest means a build identifier, not a strategy family.
See [supplementary research](supplementary_research.md) for the lab overview and
[submitted-strategy validation](line_b_and_submission.md#11-the-cross-audit)
for the separate audit.

> Every experiment listed here was run **after** the competition results were
> announced (2026-09-05 to 2026-09-09), on the local lab only. None of them
> touches the platform evaluation; none changes a competition result. Each row
> exists to support, correct, or qualify one specific sentence in the writeup
> (README.md front page or the `docs/` sections) or the logs, and every number cited in those sentences traces to a result
> file under `docs/reruns/`. Raw per-session dumps too large for the repo are
> listed in §D with their contents described; they live in a private archive
> alongside the scripts (which import the private single-file builds and
> therefore cannot be published — see `code/NOTE.md`).

Flow regimes (single-bot drivers): `calm_dumb`, `mixed`, `toxic` = the three `SCENARIOS` of `harness.py` (sharp-flow fraction and noise over-pay rising in that order). Capital: drawn per seed from {10, 20, 40} exactly as `harness.main()` does, except rows 14–16 (fixed capital per regime: calm 10 / sharp 0.05, mixed 20 / 0.20, toxic 40 / 0.40). Sessions are 40 trading days unless stated.

FOK split / RFQ tie conventions (lab assumptions, not platform rules — `code/NOTE.md`):
- **C-single**: FOK quantity split `floor(q/n)` per accepter, remainder unallocated; if `q < n` the first `q` accepters in list order fill one lot each (the bot is first); equal-price RFQ ties route to the bot first (stable sort, bot inserted first).
- **C-tourn**: same floor split; equal-price ties shuffled with the flow RNG (seat order otherwise as listed).
- **C-var**: convention is itself the treatment (rows 17, 22, 23).
- **C-none**: no competing accepters / no session flow (unit probes, census, audit probes).

Interpreters: Python 3.11 (uv-managed) for every run of rows 11–13 and for the 2026-09-09 regeneration of rows 1–7, 14–18, 25–30; Python 3.14 (Homebrew) or 3.11 for the rest. The campaign's 3.11/3.14 alignment check found bit-identical P&L, and the one file regenerated under 3.11 that had an earlier copy (`measure_rows.json`, row 1) is byte-identical to it. Paired deltas are always same seed, same warm-up length, same regime; "SE" is the standard error of the paired mean; "wins" counts sessions in which the bot ranked first among the seats.

## D. Session-count reconciliation and what is not in `docs/reruns/`

- Rows 8 and 11 are each a **three-arm grid of 7,200 sessions** (2,400 per arm: 2,100 at 15–45 days + 300 at 250). A *pair* (A/B, or ramp) is 4,800 of those sessions = 2,400 paired deltas (2,100 at 15–45). The phrase "7,200 sessions per pair" in an earlier draft is wrong. The seamed driver's full grid had no bankruptcies; the corrected grid had one, in the mid-campaign build. The final v13 build had 0/2,100 at 15–45 days under each driver (4,200 runs across the same seed grid), or 0/2,400 each including the 250-day controls. The corrected-driver ramp-off arm separately had 0/2,100 at 15–45 days. Reusing an arm in a second comparison does not create additional sessions.
- Lab sessions summed over rows 1–18, 20–24, 27–28: ≈ 44,000 single-bot or tournament sessions; rows 19, 25, 26, 29–31 are pricing/unit probes with no session flow; row 32 is a comparison of platform transcripts, not a lab run.
- Left out of `docs/reruns/` for size, all retained in the private archive: per-session raw arrays for rows 8 and 11 (`results_n100.json`, `results_combined_n100.json`, ≈ 300 KB each; key layout `warmup|regime|seed` → `[pnl, rank, bankrupt, fills, capital]` per arm), the per-seat raw JSONs behind row 21 (8 files, ≈ 160 KB; summarized in the two F01 files), the per-session seam rows of row 1 (`measure_rows.json`, 95 KB), the per-session E34/E50 arrays (child stdout, regenerated on demand), the five raw grids behind rows 17–18 (`res_*.json`, 3.4 MB in total; `analyze.py` reduces them to the published table), the per-seed A/B arrays and world-trace hashes behind row 20 (`ab_*.json`, `trace_*.json`, ≈ 35 KB; summarized), and the private-only outputs of row 32 (the transcripts themselves and any script line that prints platform run identifiers).
- Scripts (drivers, patches, probes, summarizers) are not published because they import the private single-file builds; the private archive index lists every one of them with the command that produced each result file.
